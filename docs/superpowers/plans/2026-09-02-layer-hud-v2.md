# Layer HUD v2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Extend the overlay with three appearance/config features on top of v1: configurable base-layer and grab-mode outlines, an elegant multi-layer name strip (replacing the single active-layer badge), and category icons for the hold/tap-hold/double-tap key legends.

**Architecture:** Same as v1 — Rust `Config` struct (JSON, `#[serde(default)]`) round-tripped through `get_config`/`set_config`, broadcast to the webview via the existing `config-changed` event; the webview applies theme values as CSS custom properties and re-renders the board DOM. No new Tauri commands, no new events — this plan only adds fields to the existing config and DOM/CSS to the existing renderer.

**Tech Stack:** Rust, Tauri 2, plain JS (ES modules), `node --test` for JS units, `cargo test` for Rust units.

**Spec:** `docs/superpowers/specs/2026-09-02-voyager-hud-design.md` (v1 spec — this plan was scoped through an in-chat brainstorm, not a separate v2 spec doc; requirements are captured directly in each task below).

## Global Constraints

- macOS only; no changes to build prerequisites from v1.
- No JS framework, no npm dependencies. JS is ES modules; pure logic lives in `.mjs` files imported by both the webview and `node --test`. DOM-manipulating code (`hud.js`) is verified manually via `cargo tauri dev`, matching the v1 pattern — it is not unit tested.
- Config additions follow the existing style: `snake_case` Rust fields, `#[serde(default)]` on the struct (no per-field defaults needed — `Config` has a manual `Default` impl), one slider/color-picker/checkbox row per field in `settings.html`, wired with the existing `bind`/`bindNumeric` helpers in `settings.js`.
- Theme values reach the overlay as CSS custom properties set in `hud.js`'s `applyTheme()`, consumed via `var(--x, <fallback>)` in `style.css` — never hardcode a themed value directly in CSS.
- Default values for the new outline fields (chosen to reproduce today's hardcoded look exactly):
  - Base-layer outline: `base_outline_enabled: true`, `base_outline_color: "#78b4ff"`, `base_outline_opacity: 0.6`, `base_outline_width: 2.0` (reproduces today's `rgba(120,180,255,0.6)` 2px outline).
  - Grab-mode outline: `grab_outline_enabled: true`, `grab_outline_color: "#ffdc78"`, `grab_outline_opacity: 0.9`, `grab_outline_width: 2.0` (reproduces today's `rgba(255,220,120,0.9)` 2px outline).
- User rule: run the `code-review` skill before every commit.

```js
function applyTheme(config) {
  const st = document.documentElement.style;
  st.setProperty('--board-bg', hexToRgba(config.bg_color, config.opacity));
  st.setProperty('--char-opacity', config.char_opacity);
  st.setProperty('--text-color', config.text_color);
  st.setProperty('--legend-color', config.legend_color);
  st.setProperty('--border-color', hexToRgba(config.border_color, config.border_opacity));
  st.setProperty('--border-width', `${config.border_width}px`);
  st.setProperty('--key-fill', hexToRgba(config.key_fill_color, config.key_fill_opacity));
  st.setProperty('--base-outline', hexToRgba(config.base_outline_color, config.base_outline_opacity));
  st.setProperty('--base-outline-width', `${config.base_outline_enabled ? config.base_outline_width : 0}px`);
  st.setProperty('--grab-outline', hexToRgba(config.grab_outline_color, config.grab_outline_opacity));
  st.setProperty('--grab-outline-width', `${config.grab_outline_enabled ? config.grab_outline_width : 0}px`);
}
```

export function setActiveLayer(n) {
  document.querySelectorAll('.layer').forEach((el) => {
    el.classList.toggle('active', Number(el.dataset.layer) === n);
  });
  document.querySelectorAll('.layer-chip').forEach((el) => {
    el.classList.toggle('active', Number(el.dataset.layer) === n);

  document.querySelectorAll(`[data-triggers-layer]`).forEach((el) => {

}
